# ZeroLatency DS v2: handoff for Next.js + Tailwind

Source of truth: `../tokens.json`, built by `../scripts/build-tokens.mjs` from values measured in the 200 reference app frames (`../frame-audit.md`). Everything in this folder that holds values is generated from it, so don't edit those files by hand.

| File | What it is |
|---|---|
| `tokens.css` | CSS variables for both themes, generated by `scripts/gen-css.mjs` |
| `tailwind-theme.css` | Tailwind v4 bridge (`@theme`), generated by `scripts/gen-css.mjs` |
| `components.css` | Reference styles for every component and pattern (`zl-*` classes), using only the variables |
| `previews/<Name>/preview.html` | The previews published in the artifact: 27 components, 9 patterns and the cover |
| `logo-mark.svg`, `wordmark.svg`, `wordmark-dark.svg` | Logo files, recoloured to the v2 accent |

Live design system (artifact): see `../design-system-link.txt`. Brand book: `../README.md`. Component docs and the contrast table: `../components.md`.

## Regenerate

```bash
node design-system/scripts/build-tokens.mjs   # palette → tokens.json + contrast-report.md (exits 1 if any pair fails AA)
node design-system/scripts/gen-css.mjs        # tokens.json → handoff/tokens.css + handoff/tailwind-theme.css
node design-system/scripts/previews.mjs design-system/handoff/previews
```

## 1. Fonts

No font packages are needed. `--font-sans` is the system UI stack (SF Pro on Apple devices, Segoe UI on Windows), which matches the reference frames. `--font-mono` is `ui-monospace, SFMono-Regular, Menlo, Consolas…`.

## 2. Load tokens, then the Tailwind bridge (Tailwind v4)

Copy `tokens.css` and `tailwind-theme.css` into `app/styles/`, then:

```css
/* app/globals.css */
@import "tailwindcss";
@import "./styles/tokens.css";          /* role vars: --bg, --text, --accent … for light and dark */
@import "./styles/tailwind-theme.css";  /* points Tailwind at var(--…) */

html { background: var(--bg); color: var(--text); font-family: var(--font-sans); font-size: 14px; -webkit-font-smoothing: antialiased; }
```

How it works:
- `tokens.css` puts the light roles on `:root`, `[data-theme="light"]` and `.light`, and the dark roles on `[data-theme="dark"]` and `.dark`. When neither is set, it follows `prefers-color-scheme`. It also carries the `prefers-reduced-motion` rule.
- `tailwind-theme.css` maps every colour to a variable inside `@theme inline`, so utilities switch theme with no `dark:` variants: `bg-bg`, `bg-bg-sidebar`, `bg-surface-raised`, `bg-surface-hover`, `bg-surface-selected`, `bg-accent`, `text-accent-fg`, `bg-tag-blue-bg`, `text-tag-blue-fg`, `text-icon-orange`, `ring-focus-ring`.
- Text roles are renamed `fg-*`: `text-fg`, `text-fg-muted`, `text-fg-subtle`, `text-fg-placeholder`, `text-fg-disabled`, `text-fg-on-tooltip`.
- The static scales keep the same names as `tokens.css`: `text-md` (14/20, the app default), `text-xs`, `text-xl`, `rounded-md` (6px), `p-4` = 16px, `md:` = 768px and `ease-standard`. The measured dimensions are exposed as `--size-*` variables (use them as `h-[var(--size-row-height)]` or in CSS). Tailwind's default palette, radii, shadows and breakpoints are reset, so only DS values exist.
- Shadows change per theme. Use the `elevation-xs|sm|md|lg|xl` utilities, which read `var(--shadow-*)`, not `shadow-*`.

### Theme switching (Next.js)

```tsx
<ThemeProvider attribute="data-theme" defaultTheme="system" enableSystem>{children}</ThemeProvider>
```

Put `suppressHydrationWarning` on `<html>`. `attribute="class"` also works.

## 3. Rules the build must keep

- Use **role tokens** in components. Primitives (`gray-*`, `ink-*`, `blue-*`) are only for building roles.
- **Blue means "act" or "on".** Accent fills are for the one primary action per region, the unread dot, checked checkboxes and the active Filter tool. Selection and hover are neutral (`surface-selected`, `surface-hover`).
- **Labels use the tag pairs** (`tag-*-bg` + `tag-*-fg`). View and status glyphs use `icon-*` and always sit next to a word.
- **Focus-visible:** `outline: 2px solid var(--focus-ring); outline-offset: 2px` (Tailwind: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus-ring`). Rows and list items take it inset (`-outline-offset-2`). Inputs: 1px `focus-ring` border + `0 0 0 3px var(--focus-halo)`.
- **Contrast:** every text/ground role pair passes WCAG AA in both themes (`../contrast-report.md`). `text-placeholder` is below AA by design, so use it only for placeholders and hints.
- **Density:** rows 38px (32px compact), sidebar items 30px, controls 28px, chips 20px. Don't round them to other values.
- **Motion:** hover `--duration-fast`; menus, panels and toasts enter with `--duration-slow` and `--ease-enter`. Under reduced motion only opacity fades remain.
- **Never** use the reference product's name, logos, icons or screenshots. Product visuals are the code-built `AppShell` / `ScreenshotFrame` with fictional data. Testimonials stay marked "Placeholder".

## Breakpoints

| Token | Min width | Use |
|---|---|---|
| `sm` | 375px | phone baseline (mobile-first) |
| `md` | 768px | tablet: marketing grids go two-up; rows go back to one line |
| `lg` | 1280px | desktop: app shows sidebar + list + peek/panel (below 1024px only the list shows) |
| `xl` | 1536px | wide: marketing content stays at max 1120px |
