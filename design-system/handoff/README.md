# ZeroLatency DS: handoff for Next.js + Tailwind

Source of truth: `../tokens.json`. Everything in this folder that holds values is generated from it, so don't edit those files by hand.

| File | What it is |
|---|---|
| `tokens.css` | CSS variables for both themes, generated by `scripts/gen-css.mjs` |
| `tailwind-theme.css` | Tailwind v4 bridge (`@theme`), generated by `scripts/gen-css.mjs` |
| `components.css` | Reference styles for every component and pattern (`zl-*` classes). They use only the variables. |
| `previews/<Name>/preview.html` | The previews published in the artifact (14 components, 7 patterns and the cover) |
| `logo-mark.svg`, `wordmark.svg`, `wordmark-dark.svg` | Logo files. The wordmark text is outlined from Instrument Sans 600. |

Live design system (artifact): see `../design-system-link.txt`. Component docs and the contrast table: `../components.md`.

## Regenerate

```bash
node design-system/scripts/build-tokens.mjs   # palette → tokens.json + contrast-report.md (exits 1 if any pair fails AA)
node design-system/scripts/gen-css.mjs        # tokens.json → handoff/tokens.css + handoff/tailwind-theme.css
```

## 2. Load tokens, then the Tailwind bridge (Tailwind v4)

Copy `tokens.css` and `tailwind-theme.css` into `app/styles/`. Then:

```css
/* app/globals.css */
@import "tailwindcss";
@import "./styles/tokens.css";          /* role vars: --bg, --text, --accent … for light and dark */
@import "./styles/tailwind-theme.css";  /* points Tailwind at var(--…) */

html { background: var(--bg); color: var(--text); font-family: var(--font-sans); }
```

How it works:
- `tokens.css` puts the light roles on `:root`, `[data-theme="light"]` and `.light`, and the dark roles on `[data-theme="dark"]` and `.dark`. When neither is set, it follows `prefers-color-scheme`. It also carries the `prefers-reduced-motion` rule.
- `tailwind-theme.css` maps every color to a variable inside `@theme inline`, so utilities output `var(--bg)` and switch theme with no `dark:` variants: `bg-bg`, `bg-surface`, `bg-accent`, `text-accent-fg`, `border-border-strong`, `ring-focus-ring`.
- Text roles are renamed `fg-*` in Tailwind to avoid `text-text`: `text-fg`, `text-fg-muted`, `text-fg-subtle`, `text-fg-disabled`, `text-fg-inverse`, `text-fg-on-emphasis`.
- The static scales (type, weights, radii, 4px spacing, breakpoints, easings) are written out with the same names and values as `tokens.css`. That gives you `text-sm` (14/20), `text-display`, `rounded-md`, `p-4` = 16px, `md:` = 768px and `ease-standard`. Tailwind's default palette, radii, shadows and breakpoints are reset (`initial`), so only DS values exist.
- Shadows change per theme. Use the `elevation-xs|sm|md|lg|xl` utilities, which read `var(--shadow-*)`, not `shadow-*`.
- Durations: `duration-[var(--duration-fast)]`, or plain CSS `transition: … var(--duration-fast) var(--ease-standard)`.
- There is also a `dark:` variant for the rare case that needs one. It matches `[data-theme="dark"]` and `.dark`.

### Theme switching (Next.js)

Set the attribute on `<html>`, for example with `next-themes`:

```tsx
<ThemeProvider attribute="data-theme" defaultTheme="system" enableSystem>{children}</ThemeProvider>
```

`attribute="class"` also works, because `.dark` and `.light` are supported. Put `suppressHydrationWarning` on `<html>`.

### Tailwind v3 (if the project is pinned to v3)

```js
// tailwind.config.js (excerpt): same idea, colors point at CSS variables
const roles = ['bg','bg-subtle','surface','surface-raised','surface-sunken','surface-hover','surface-selected','surface-inverse','surface-emphasis','border','border-strong','accent','accent-hover','accent-active','accent-fg','accent-subtle','accent-subtle-hover','accent-text','accent-border','focus-ring','focus-ring-emphasis','overlay',
  ...['success','warning','error','info'].flatMap(s => [s, `${s}-fg`, `${s}-text`, `${s}-subtle`, `${s}-border`]), 'error-hover'];
module.exports = {
  darkMode: ['variant', ['&:where([data-theme="dark"], [data-theme="dark"] *)', '&:where(.dark, .dark *)']],
  theme: {
    screens: { sm: '375px', md: '768px', lg: '1280px', xl: '1536px' },
    colors: {
      transparent: 'transparent', current: 'currentColor', white: '#fff',
      ...Object.fromEntries(roles.map(r => [r, `var(--${r})`])),
      fg: 'var(--text)', 'fg-muted': 'var(--text-muted)', 'fg-subtle': 'var(--text-subtle)', 'fg-disabled': 'var(--text-disabled)', 'fg-inverse': 'var(--text-inverse)', 'fg-on-emphasis': 'var(--text-on-emphasis)',
    },
    fontFamily: { sans: 'var(--font-sans)', mono: 'var(--font-mono)' },
    boxShadow: { none: 'none', xs: 'var(--shadow-xs)', sm: 'var(--shadow-sm)', md: 'var(--shadow-md)', lg: 'var(--shadow-lg)', xl: 'var(--shadow-xl)' },
    borderRadius: { none: '0', xs: '4px', sm: '6px', md: '8px', lg: '12px', xl: '16px', '2xl': '24px', full: '9999px' },
    // fontSize: read from tokens.json → [size, { lineHeight, letterSpacing }]
  },
};
```

In v3 the variables have no alpha channel, so opacity modifiers such as `bg-accent/50` don't work. Use the `*-subtle` roles.

## 3. Rules the build must keep

- Use **role tokens** in components (`bg-surface`, `text-fg-muted`). Primitives (`neutral-500`, `accent-600`) are only for building roles.
- Use **one accent**. Accent fills are for the one primary action, the unread dot, selection and AI labels. Status colors always come with a word or an icon.
- **Focus-visible** is `outline: 2px solid var(--focus-ring); outline-offset: 2px` (Tailwind: `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-focus-ring`). Inside the CTA band (`bg-surface-emphasis`), use `outline-focus-ring-emphasis`.
- **Contrast**: every text/background role pair passes WCAG AA in both themes (see `../components.md` → Contrast). Any new pairing has to pass too: re-run `build-tokens.mjs` after you add it to the pair list.
- **Motion**: hover and press use `--duration-fast` with `--ease-standard`. Things entering use `--duration-slow` with `--ease-enter`. Under reduced motion, only opacity fades remain; `tokens.css` enforces this globally.
- **Logo**: use `wordmark.svg` on light, `wordmark-dark.svg` on dark, and `logo-mark.svg` as the favicon and app icon. Keep clear space of half the mark's width around it.
- **Notion Mail reference is allowed (D12).** For now the project is for personal use only, so Notion Mail assets and screenshots can be used directly, and its colors, fonts and layouts can be copied. Replace them when the product is rebranded. Testimonials stay marked "Placeholder".

|---|---|---|

| `xl` | 1536px | wide: content stays at max 1152px, margins grow |
